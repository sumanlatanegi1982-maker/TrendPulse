Hi everyone. I built TrendPulse, a YouTube trend analytics website that helps content creators find what is trending in their specific stream, powered by BrightData Scraper Studio.

Let me show you how it works.

This is the TrendPulse dashboard. When you open the website, you see trending YouTube videos from the last seven days across all content categories.

At the top, you can see four stat cards showing total trending items, number of videos, number of shorts, and average views.

Below that, we have the analytics section. This bar chart shows the view distribution, how many videos fall in each view range from zero to ten million plus views. Next to it, we have the top five trending videos ranked by views, with clickable links that open the actual YouTube video.

And here is the stream comparison chart, showing which content categories like gaming, education, and tech get the most average views.

Now let me show you the stream filtering. When I click on Gaming, you can see only gaming videos appear. Each video has the stream tag showing gaming, and the content is completely different from the All tab.

When I click on Education, the videos change completely. Now we see Python tutorials, math lessons, and physics videos. The filtering is precise, no mixed content.

We also have content type tabs. When I click on Shorts, only videos under sixty seconds are shown. When I click on Videos, only long form content appears. The system automatically detects shorts based on video duration.

You can also toggle between light and dark themes using this button. Light mode gives you a white and red theme, and dark mode gives you a black and red theme.

Now let me talk about the BrightData integration. TrendPulse uses the BrightData pre-built YouTube scraper called Discover by Keyword. The dataset ID is gd_lk538t2k2p1k3oos71. For each stream, we send a keyword search to BrightData. For example, when a user clicks Gaming, we send the keyword gaming highlights to the BrightData API, and it returns structured JSON with video titles, views, likes, channel names, upload dates, and thumbnails. No parsing required on our end.

Here in the terminal, you can see the self-healing system in action. When BrightData returns broken records with missing fields, the system logs the broken record and re-scrapes only that record. It retries up to three times. You can see the log saying, HEAL Cycle 1, all records valid.

The scraper runs on a schedule automatically every four hours, so new trends come in while old ones get replaced. But to save BrightData credits during development, I built a cache mode. When I scrape once with the real API key, the data is saved to a file called cached_data.json. Then I set USE_CACHED_DATA to true in my environment file, and the app loads from that file instead of calling the API again. Zero credits used during debugging.

Here on the BrightData dashboard, you can see my scraper and the free credits counter showing 3167 out of 5000 credits remaining.

So that is TrendPulse. YouTube trend analytics with self-healing scrapers, scheduled auto-refresh, seven-day recency filtering, and credit-saving mode. Built with BrightData Scraper Studio for Into the Scrape-Verse. Thank you for watching.
